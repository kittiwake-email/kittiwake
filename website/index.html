Kittiwake

A massively scalable mail platform built to replace Dovecot.

Kittiwake stores mail in Ceph RADOS and metadata in MariaDB, and sits behind Postfix, which keeps doing what it does best: receiving and filtering mail from the internet. Kittiwake takes delivery over LMTP and serves mailboxes over IMAP, POP3, JMAP and submission.

The kittiwake is a small sea-going gull that nests on cliffs in colonies of hundreds of thousands: a bird, like the dove it succeeds, that lives at sea and at scale.

Built for scale

  • Designed for a million mailboxes, each holding up to 150k messages spanning decades.
  • One RADOS object per message with deduplicated attachments; no per-mailbox file system.
  • Every component runs as its own process and scales independently; all state lives in RADOS and MariaDB, so any node can serve any mailbox.
  • Mail data can be spread across many Ceph clusters.
  • Client-side encrypted backups to any S3-compatible store, with restore and export.

Proof of concept. Kittiwake works, but it has not been tested at large scale yet. You are welcome and encouraged to try it on real workloads and at real sizes. If you do, please open an issue or write to Wido den Hollander with what you found.
