Kittiwake scalability, security and integrity review — 2026-10-23

Scope: Go product, with IMAP the initial primary workload. Mail is in Ceph
RADOS; production identity, sessions and queues are in MariaDB.
Commit convention: never mention the coding assistant, model or agent in Git
commits, including subjects, bodies, session trailers and co-author trailers.

Findings (status initially OPEN; update with implementation and evidence):
01 HIGH: Change log published before folder/message commit; consumers can
   advance past a record that does not yet exist. Reproduced on memory RADOS.
02 HIGH: Record mutations are unconditional outside root CAS. Concurrent
   mark-seen produced total=1/unseen=-1; flags can be lost and records revived.
03 HIGH: MOVE/REMOVE have no durable recovery. Torn moves misdirect location;
   failed removals leave retention entries for live mail, later purged.
04 HIGH: Orphan sweep treats retention lookup failure as empty and does not
   revalidate deletion candidates; transient errors/concurrent moves risk loss.
05 MEDIUM: Hard quota admission uses stale/non-atomic usage; recalculation
   overwrites concurrent counter updates using an earlier scan.
06 HIGH: Attachment download checks mailbox access, not attachment membership.
   Cross-mailbox attachment retrieval by hash reproduced on shared storage.
07 HIGH: delivery.Import omits actor/write authorization. Read-only import
   reproduced; IMAP APPEND and JMAP Email/import reach it.
08 HIGH: Established IMAP actors retain revoked account/role/service access;
   JWT OAuth login ignores disabled accounts and account lookup errors.
09 HIGH: Recovery code is checked before atomic account update, then removed
   by stale index; concurrent use can succeed twice or remove another code.
10 MEDIUM: Password cache key omits protocol, bypassing per-service policy in
   combined-mode daemons after a successful login on another service.
11 HIGH: Ascending listing rereads an entire 65,536-entry shard per 1,000-item
   page. SELECT of a dense 150k folder decodes roughly 9m records. Recalc and
   general JMAP queries share the path; sessions retain full records.
12 HIGH: ENVELOPE/BODYSTRUCTURE/header FETCH reconstructs full MIME including
   external attachments; ordinary raw reads first probe absent .raw objects.
13 MEDIUM: Daily attachment GC scans all objects and refs; metadata lookup
   enumerates refs too. Cost grows with all live mail and attachment sharing.
14 MEDIUM: librados Get uses Stat then old-sized Read; concurrent growth can
   truncate JSON. Wrapper read count understates actual RADOS round trips.

Completed follow-up work:
- Admin imports now pass. Root cause was inconsistent fixture clocks: auth used
  2026-10-21 while delivery used wall time, correctly rejecting an expired token.
  Fixed the clocks, not the authorization/expiry enforcement.
- Added SaveSent, restricted to the actor's own mailbox, send permission, Sent
  folder and Seen flag. Send-only accounts retain Sent copies without acquiring
  arbitrary Import privileges. Cross-mailbox and ordinary-import denial tested.
- JMAP uploads require write permission and respect mailbox state/legal hold;
  uploaded-blob retrieval requires read access. Regression tests cover role checks.
- Journal root-only operations use one atomic transaction; cached initial roots
  are protected by CAS and stale semantic failures re-read before rejection.
  Target-version reads run concurrently; completion uses the known prepared root
  version, reading again only after a conflict. No weakening of recovery fences.
- Delayed recovery helper regression verifies newer flags survive and removed
  messages stay removed. Stale-root regression verifies newly created folders
  on another daemon do not cause false rejection.
- Recovery performed by readers sends best-effort watcher notifications. Clients
  still use polling as fallback. Invalid serialized transaction opcodes fail closed.
- Orphan sweeps stream candidates instead of keeping a pool-sized slice. Message
  enumeration also streams: raw copies get a document existence check instead
  of retaining all document names. Retention-read failure preserves message data
  in a fault-injection regression test. Purge rechecks holds between messages.
- Export uses RawStored to avoid absent-raw probes for new ordinary messages.
- README/AGENTS updated for format 2, journal commit semantics, object layout,
  candidate GC, MIME metadata, and the required quiesced upgrade.

Remaining limits / follow-on work (do not describe as fully resolved):
- The journal's durability has measurable write cost: index-only Append/SetFlags
  are slower than the unsafe baseline. More throughput/latency work must preserve
  the publication and stale-helper invariants. No whole-platform load claim is
  made from these single-mailbox microbenchmarks.
- IMAP retains full index records per selected folder to avoid extra FETCH/search
  reads; a compact shared/session representation remains future memory work.
  Public ascending ListFolder remains a compatibility API with whole-shard reads;
  primary internal full scans now use descending cursor pages.
- Legacy MIME documents lack metadata; body-part FETCH still reconstructs full
  MIME. Backfill and selective part streaming remain future work, not performed.
- Reads are not cross-object snapshots; concurrent readers may observe newer
  records before their changes are published. State tokens come from finalized
  roots/change logs, so subsequent synchronization must still process those changes.
- Legal-hold rechecks bound a long purge's exposure but cannot make a MariaDB
  hold update atomic with a Ceph delete already in flight. Strict cross-store
  hold barriers would require additional coordination; not introduced here.
- Location tombstones and per-shard empty-object tombstones are retained for
  stale-helper safety; safe compaction needs its own protocol.
- Do not mix old and new writers or roll back after format-2 writes. Quiesce all
  old writers/workers before a future deployment. No automatic downgrade provided.
